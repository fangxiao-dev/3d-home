# 莹仔的美食收藏图鉴｜生日游戏彩蛋方案 v2

> 定位：生日礼物游戏的轻量彩蛋模块，而不是独立小游戏、第二条任务主线或单纯的贴纸制作说明。  
> 本文整合最初关于「零食虚拟模型—真实食物—画册贴纸」的讨论，以及后续确定的美食清单和视觉方案。  
> 状态说明：**已确认**是双方明确达成的方向；**建议**是为衔接游戏而提供的实现方式；**待定**不提前写成需求。

## 一、核心想法：把「你喜欢吃的，我都记得」藏进游戏

生日游戏原本是一处可以探索的私人空间。主体体验是安静地阅读画册与情书，最后进入戴王冠、摆放蛋糕、点蜡烛等生日仪式。美食图鉴在这里扮演一个与主线节奏不同的角色：轻松、日常、有烟火气，能让她在探索、阅读或回看画册时，偶然发现一个熟悉的食物。

它的情感价值不靠每款食物配一段情话，而是靠**个人化的准确性**。她常说喜欢的菠萝油、巧克力熔岩、好欢螺，以及泰国的打抛饭、非洲的 Fufu 等，放在一起就不再是泛用的美食画册，而是她自己的口味地图。某些食物还自然勾连她个人的生活经历或你们共同的经历。

> **虚拟世界负责收藏喜欢与记忆；现实生活负责继续创造这些记忆。**

这个想法直接来自最早的讨论：游戏里看见的食物，可以在画册中化为贴纸，少数还可能在现实中作为礼物出现。但**不要求每一种都有真实食物对应**。

## 二、它怎样进入整个生日游戏

### 与既有游戏结构的关系（已确认的前提）

- 游戏的主体是一个可探索的私人空间；画册和情书是场景内可翻阅的内容，生日仪式包括王冠和生日蛋糕。
- 既有讨论中，主线的推进依靠阅读与生日仪式本身，而不是地图探索任务。2048 等趣味互动另有位置。
- 美食彩蛋属于**可发现但非必需**的侧层：没有找到任何食物，也不影响画册、情书、王冠和生日仪式的正常体验。

### 四个载体如何联动

| 载体 | 作用 | 具体呈现 | 确认程度 |
|---|---|---|---|
| 游戏场景 | 「发现」 | 某些食物化为小模型、摆件、包装或贴纸，在合适的生活场景里自然出现 | **已确认方向**；具体摆放位置待场景设计 |
| 数字图鉴 | 「收藏／回看」 | 以《莹仔的美食收藏图鉴》为统一系列；食物可被查看，少量附带真实记忆或她的原话 | **已确认轻量收藏方向**；是否做独立图鉴 UI 待定 |
| 画册与情书册 | 「留下实体痕迹」 | 同系列贴纸用于书页装饰、页角、局部专题页，也可以打印成真正的贴纸包 | **已确认**，这是最稳定、最好控制的交付形态 |
| 现实食物与惊喜 | 「从虚拟走入现实」 | 选少量容易准备的实物、生日甜品或未来的兑换约定，与游戏内容呼应 | **可选**；不承诺每款都有，也不预先绑定购买 |

**建议的轻量体验示例（不是固定剧情）：** 她在游戏里的某个角落发现一块巧克力熔岩，查看后看见图鉴插画及一句简短说明；后来翻画册时，又在页面上发现同款贴纸。如果你届时准备了真正的蛋糕，这个巧合就会变成现实惊喜。没有实物，也不影响彩蛋成立。

**不要反过来做**：要求她找齐十几款食物才能开下一扇门、拿到王冠或进入生日场景。这会把本来应当安静自然的生日体验变成任务清单。

## 三、内容设计：混合形式，而不是平均分配互动

最早讨论过「装饰款—记忆款—隐藏款」三层，这个思路继续保留，但仅作为**表达层次**，不是游戏里的正式稀有度系统。

1. **日常装饰款（主体）**：更多的食物只是作为场景摆件、图鉴插画、画册贴纸出现。能被认出、觉得可爱，就完成了职责；无需每个都设计点击动画或台词。
2. **记忆款（少量）**：有真实出处的食物可以多承载一点内容，如非洲 Fufu、在非洲吃过的饼干夹心冰淇淋、泰国打抛饭，或她反复说最喜欢的菠萝油。文字应当来自真实回忆，避免 AI 杜撰故事。
3. **特殊惊喜款（极少量）**：挑最适合实现的一两种食物，延伸到现实世界。可以是她收到的实际食物，也可以是将来一起去吃的一次约定；二维码、兑换券或特殊动画属于早期创意备选，**不是已经确定必须制作的功能**。

这套内容既体现她的个人喜好，也体现你们关系里「小日子」「经常下意识想到她」的日常质感。它不需要承载王冠、时间等宏大母题，也不需要替代情书本身。

## 四、当前美食内容与视觉基准

### 当前完整图鉴视觉（已确认）

采用你最终选择的 **旅行手账贴纸风**：鲜艳但温暖、轻卡通、有一定食物质感、白色异形贴纸边、手账装饰；不要拟人化，不要变成纯写实产品照，也不要在单个物件周围塞满桌面与道具。合集排版需要留白，让小尺寸下也容易辨认。

### 目前确认图鉴样稿中已有的 16 款

热干面、泰国打抛饭、千层面、烧白／扣肉、糖醋排骨、三文鱼、非洲 Fufu、巧克力熔岩、星巴克巧克力麦芬、菠萝油、饼干夹心冰淇淋、赛百味、麦辣鸡腿堡、榴莲、瑞幸生椰拿铁、mini 小瓶可口可乐。

其中需保留的具体识别要求：

- Fufu：白色软糯主食约占画面食物的 **35–40%**，形态像被揪过而非标准圆球；酱汁、蔬菜为主，仅少量小肉块，整体是更简化的手账卡通风。
- 糖醋排骨：短节排骨上能看出肉与骨头的差别，约三块即可，不能画成一堆无法辨认的红色肉条。
- 泰国打抛饭：应明显看出**肉末**、罗勒与煎蛋，肉末不能变成豆类。
- 千层面：突出叠层面片、肉酱和奶酪，不要像颗粒豆子堆砌。
- 赛百味：长条面包，部分用赛百味包装纸包裹、露出一半。
- 榴莲：用一颗打开少许的榴莲，或仅一至两瓣果肉，避免「一大颗加几个小果肉」的拥挤构图。
- 生椰拿铁是**瑞幸**，不是星巴克；可乐是**mini 规格的小瓶**。

### 候选池：此前提出、尚未出现在当前最终样稿的食物

- 好欢螺**原味紫色包装袋**：用户提供了包装实拍参考，保留商品外观，而不是画煮好的螺蛳粉。
- 椰香卷：只画食物本体，**不要添加椰子**（包装上的椰子不是食物组成部分）。
- 芝士蛋糕：可作为贴纸，也曾讨论过可能与生日蛋糕场景呼应；未确定两者必须一致。

**明确排除／不再继续展开**：金粒门（是品牌，不是具体食物）、鱼皮、粽子、番茄、小米辣牛肉丝、春卷。初期从聊天记录收集到的其他食物不自动进入制作范围。

## 五、游戏表现与制作范围建议

### 最小可用版本（建议优先）

当前图鉴的 2D 插画可先进入画册和情书册；游戏中挑 **3–5 款辨识度强、摆放自然**的食物做可见物件。查看时能看到食物名称与插画，必要时多一句她的原话或你们的真实回忆，其余食物暂作平面装饰。

交互可以沿用既有游戏的键盘操作习惯（靠近、按 `F` 查看／互动），不必因此引入复杂收集背包或成就系统。将来如果决定增加数字图鉴页面，再让已发现项出现「已查看」状态即可；**不以收集数量驱动生日仪式**。

具体出现在冰箱、桌面、书架、食品柜还是画册页内，应取决于最后的游戏场景设计，**本文不预设房间布局**。

### 素材如何分层使用

- **2D 图鉴插画**：直接用于数字页、纸质画册、实体贴纸。
- **游戏轻量物件**：可使用面片、摆件、贴图或简化 3D 模型，不要求 16 款全部手工建模。
- **重点 3D 食物模型**：只为确实有近距离观察或互动价值的食物建模；现有拆分 PNG 用作造型／配色参考，不应误当高精度建模纹理或印刷级资产。
- **真实食物**：独立于游戏资源制作，实际可买到、能保存、能送达，再决定是否与某款游戏彩蛋对应。

### 边界与验收

这个模块成功的标准不是「收齐全部食物」，而是：她能在游戏或画册中认出几个**确实属于自己的喜好**；视觉上属于同一个系列；不会打断翻书与生日仪式的主体验；少数有记忆的食物讲的是真实故事；现实奖品没准备也不会出现无法兑现的承诺。

## 六、当前决定与待定项汇总

**已经确定**：以混合形式做系列美食贴纸；选定旅行手账贴纸风；游戏、画册、情书册多载体复用；少量食物可以转成虚拟模型与现实惊喜；不将收集设计为主线强制任务；当前图鉴中采用这 16 款样稿造型。

**暂不决定**：游戏里究竟放几处、具体藏在哪里；是否专门做可翻的数字图鉴 UI；哪些食物是真实奖励；二维码和兑换券是否落地；哪些 2D 食物升级为精细 3D 模型；候选池三款是否纳入下一版完整图鉴。

**下一步在整个生日游戏中的接入方式**：等主场景和核心交互基本成形，选择少量合适的放置点，将现有图鉴插画做成游戏物件/界面元素；与此同时把同款贴纸用于画册和情书册。游戏整体完成度优先于把美食图鉴做成第二套完整系统。
