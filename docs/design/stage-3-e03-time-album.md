## 1. 一句话概念

在客厅电视下方的柜面上有一本可翻阅的时间画册。它记录两个各自走过很远的人：2016 年短暂相识，后来十年各过各的日子；真实的朋友圈互动在两条轨迹之间形成一条微弱的星河；2025 年 11 月开始重新聊天，星河逐渐变暖、两条线靠近；2026 年元旦成为“我们”，接着是一册温暖、琐碎、可爱、也有认真承诺的生活手账。

**总体体验是一次持续的翻阅，而非三个需要切换的场景。** 夜色、黎明与手账，是同一本纸质画册上的连续变化。

## 2. 设计的三个核心层面

### 2.1 叙事

- **2016—2025.11 前**：两个人的生活各自成立；长期少聊天，但朋友圈联系并不稀少。不要把过去十年写成“早就命中注定”，也不要强行补全对称故事。
- **2025.11.13—2026.01.01**：从一场聊天开始真正靠近。这个大约七周的阶段承担可见的视觉融合：双轨逐渐向内，星河变暖，书页上的时间轴从远景原地伸缩到近景。
- **2026**：确认关系后共同叙事已经成立，即使大部分时段物理上异地。用一条**外形连续、内部保留双股纹理的共同轨迹**表示“我们”；异地仍由两地天空、视频交流等内容表现，不再要求主轨迹按实际见面日期反复拆开。

### 2.2 画册形式

延续已有的双页纸质相册：米白纸张、轻微纸纹、拍立得/胶带/票根、纸条、真实照片和少量原话。前史页相对独立而克制，2026 页可以更丰富、更手账化，但字体、相册装订和纸张材质统一。

底部是一条跨两页的固定时间带，**不是第三块独立的网页导航**。它既呈现叙事，又负责跳转。

### 2.3 运动与情绪

时间本来抽象，现在由**一艘在星河上缓慢航行的小舟**呈现：翻页时小舟驶过，经过的星群和水面发生局部生物荧光般的响应。到 2026 元旦，小舟靠岸停住；随后运动的载体交给共同轨迹上的一串小光点，以暖光接力的方式传导，抵达并点亮事件图标。小舟不再随 2026 事件移动，也不是固定位置光标。

完整交互与效果定义见时间轴组件文档。

### 2.4 持续保留的内容原则

1. **关系不等于物理距离，也不等于互动次数。** 轨迹代表各自生活与共同叙事；相聚日期仍是真实回忆，2026 的共同丝带不随异地拆分。
2. **时间线既是内容又是导航。** 翻页带动时间指针，点击记忆节点跳转；没有素材的年份仍然存在，不编造内容。小舟与暖光接力承担指针的视觉角色，详见组件稿。
3. **相遇前的记录不需要对称。** 可以只放一人的照片，也可以同年双人对照；不强求每年凑齐两人，不强求照片意义相似。前史独立克制，2026 的照片、票根、小标签、私人语言和琐碎物件逐渐丰富，纸张与字体始终统一。
4. **让照片说话。** 图片、物件和日期为主，少量真实文字作注解；完整情书归 E04。原始聊天统计、研究笔记和所有情话不直接堆进页面。画册不是恋爱史考试、第二本情书或生日仪式的必做任务。
5. **她走出第一步，剩下的路他来奔赴。** 求婚词「谢谢走出的第一步。剩下的路，我都会勇敢向你奔赴。」贯穿首尾。她先开口的三处为 2017-07-27「在不」、2025-11-13「又是一个时差党」、2026-01-01「是的吧？」；他奔赴的四步为 2026-02-23 飞回宜昌、09-19 回国、10-03 求婚、10-19 领证，并向未来继续延伸。这两组必须成对出现，不能只留下她主动的前半段。七枚脚印、跨年桥接与悬停规则见组件稿 §5.4。
6. **私人回忆不做刻意回避。** 用户已确认画册内容属于私人回忆；尊重原句、说话人和真实素材，不擅自删去关系背景，也不擅自补写。少量节选的篇幅选择仍适用；公开上传或发布私人资料需要另行明确授权。

其中「只属于我们的词典」「会想起你的东西」「两地天空」「聊天与通话统计」**不各自强制成为独立章节**：更适合挑少量内容嵌入 2026 手账页。可考虑选一两个有趣的数据当角注，但不要制作统计仪表盘；通话记录保留为内容资料；针脚表现已按本轮确认取消，不另造统计仪表盘。

**私人语言槽位**：2026 年的手账页各留一个小标签位置，每页至多一句真实原话。目前仅放一个示例：天空页「我脑子里想不到第二个人」。其余句子由用户自行挑选，不由 Agent 预填。

## 5. 三处留白与私人表达

保留三种含义不同的留白：跨年视频忘了截图（手机通话框）；求婚现场没有录像（空白拍立得）；尚未发生的未来（未显影相纸）。它们不是惋惜或“照片不重要”的教育，而是幸福发生时未必能记录下来。

文案仍只节选少量真实原话；完整情书属于 E04。2026 的私人语言应以纸条/标签呈现，不应因模板样式丢失而变成普通大字。左页照片、脚注和文字不得重叠。原型中这些作为**页内排版修复项**，与时间轴方案分开验收。

### 5.1 留白的具体含义

**不是“没拍所以遗憾”，而是“有时候我们忙着幸福”。** 她喜欢出片，你想记录 Vlog；正因如此，未留下影像的亲密时刻才显得真实。相册不能反过来教训她不要拍照，也不应故作深沉地空出十几页。

采用三处不同含义的留白：

- **跨年视频**：本应留下一张截图，结果忘了；空相框旁放实际留下的几句聊天。相框做成**竖屏手机通话框**。
- **求婚**：没有刻意找人拍下现场；旁边保留戒指照片和求婚词节选，**现场本身留给记忆**。相框做成**空白拍立得**。
- **未来**：尚未发生，留一张真正等着以后被填满的空相纸。相框做成**尚未显影的相纸**，带乳白雾感。

三处相框形状不同，翻到第三个时她能自己意识到这三次空白不是同一回事，无需文字解释。

求婚的空相框与下一单元丰富的领证照片相邻，形成一次视觉节奏变化。不要每次空白都加长篇解释，更不要把留白做成游戏谜题。

### 5.2 私人语言与尾页

2026 手账页各留一个小标签槽位，**每页至多一句真实原话**。目前只确定天空页示例「我脑子里想不到第二个人」（2026-07-29 晚霞，莹仔）；其余由用户自行挑选，Agent 不预填。尾页使用她的承诺「明年之后的每个生日我都陪你一起过」（2026-10-16），让她在生日当天读到；这段尾页文案已单独确认，不代表可以为其他页自动补句。

求婚页必须有「他奔赴的路」卡片，节选「谢谢走出的第一步。剩下的路，我都会勇敢向你奔赴。」并按 02.23 → 09.19 → 10.03 → 10.19 排列。完整求婚词不搬入画册；另一个可用节选为「让我们的求婚被记忆不断的加工美化」。

## 6. 空间、交互及技术边界

- **入口**：客厅电视柜实体相册，接近后 `F` 打开；`Esc` 返回游戏，保留本次会话的阅读位置。退出返回原位置。不进入背包，不影响王冠、蛋糕、2048 或仪式条件。不可要求先读完画册才能触发其他彩蛋。
- **布局**：保持双页占主体、镜头保留客厅空间感，优先保障照片、文字和时间带清晰；时间带尺寸与布局见组件稿 §2.1。双页外壳统一，单人、对照与拼贴页内部自由排版，不模拟复杂物理翻书。
- **输入**：左右翻页按钮、方向键、点击时间节点直接跳转，可选时间目录；不增加必须学习的目录操作，不设阅读任务或解锁条件。进入画册隔离角色移动和游览镜头，关闭后恢复；电脑浏览器是交付目标，触屏仅为可选增强。导航及装饰元素规则见组件稿 §6。
- **数据**：HTML 和 Godot 均以 `godot/content/album/album.json` 为权威内容源，游戏照片共用 `godot/content/album/images/`；原始互动数据留在 E 盘，v1.2 视觉参考和 v1.3 共用 JSON 语义块模板保留；原有 `quarters`、`real_stars`、`call_hours` 保留。HTML 视觉原型若直接离线打开，可使用清楚标注的演示内容回退。
- **实现顺序**：先 HTML 对齐视觉/交互，后映射到 Godot 原生绘制与 Tween；不要求引入新的引擎或 HTML Overlay。
- **时间范围**：此次只设计到 2026，结尾保留“未来”叙事性尾页。往后多年要增补时重新设计，而不是现在提前造无限延伸的刻度系统。

### 6.1 跨彩蛋关系

- **E04 情书**：画册提取真实时间、照片和少量原话，完整的《Day One》《汉堡王》《理想主义与王冠》等留在文集。可选文字指向文集，但不必为此新增复杂的跨房间传送。
- **E01 王冠 / E02 蛋糕与仪式**：时间画册独立可用，不作为仪式的前置条件；未来页与生日演出的联动仅作候选增强。
- **C01 2048**：在旅行或飞机回程页留一个生活脚注，不再内嵌第二套 2048。
- **C02 百醇 / E05 猫抓痕**：可以在画册中一笔带过，也可以完全留给场景实物，不必强制交叉引用。
- **实现**：复用 Godot 已有的 F 交互、输入隔离、阅读页状态及退出恢复机制；为相册新建数据驱动的记忆单元、可点击时间带、缩放与星点显示。网页首版不用新增自由抓取、物理翻书或复杂视频剪辑系统。

### 6.2 技术方案依据与后续 Godot 验证

以下保留旧稿的技术评估、备选方案和推进建议，帮助解释既有选择；其中“建议做 Spike”是原始建议，不把已经存在的 Stage 3 集成描述为尚未开工，也不授权本轮修改 Godot。v1.4 的下一步仍是原生 UI 视觉迁移，实际状态见 [当前状态](../status.md)。时间轴的具体实现标准统一见组件稿 §8。

现有 Godot + Blender 技术路线可以支持画册，无需更换引擎或制作可翻页的 3D 书模型。

建议沿用 Stage 1 情书文集的方案：

3D 小屋负责承载画册入口，Godot 的 2D UI 负责呈现画册内容。

玩家走到画册前按 `F`，进入覆盖在游戏画面上的阅读界面。界面可以保留小屋背景，展示完整的双页相册、照片、时间轴和动画；退出后恢复正常的 3D 游览。

画册的目标是融入游戏画面、提供自然的阅读交互。2D UI 比物理模拟的 3D 翻页更易实现，也能让照片和文字保持清晰。

#### 现有实现的复用基础

仓库已有两个可供复用的实现：

- `godot/letters_ui.gd`：使用 `CanvasLayer` 构建双页阅读界面，包括纸张、文字、图片、翻页和返回。
- `godot/phone_2048.gd`：同样使用 `CanvasLayer`，并且通过 `Tween` 实现方块滑动、缩放等动画。

`playroom.gd` 也已经有完整的交互模式切换、释放鼠标、Esc 返回游览等逻辑。

E03 可复用上述系统，主要新增画册视觉组件和时间轴逻辑。

#### HTML 效果与 Godot 实现映射

| HTML 原型效果     | Godot 实现方法                      | 判断     |
| ------------- | ------------------------------- | ------ |
| 双页手账、纸张、贴纸    | `Control`、`Panel`、`TextureRect` | 容易     |
| 多张照片自由排版      | `TextureRect` + 旋转、缩放、层级        | 容易     |
| 点击节点跳转、左右翻页   | `Button` + 页面状态                 | 容易     |
| 双轨曲线和记忆节点     | 自定义 2D 绘制或 `Line2D`             | 可实现    |
| 星星逐个亮起、熄灭     | `Tween` 驱动透明度、亮度                | 可实现    |
| 2026 年时间轴动态放大 | 插值改变时间映射和曲线位置                   | 需要专门开发 |
| 空相框、求婚与领证转场   | 2D 图片和简单过渡动画                    | 容易     |

Godot 原生提供可自定义的 UI 控件、2D 曲线绘制和属性插值动画，这些都是正式支持的能力。


Godot 可以实现同样的视觉和交互效果，但不能直接运行 HTML/CSS。CSS 布局、SVG 时间轴和动画需要转换为 Godot 对应的实现。可先用 HTML 对齐视觉效果，再在迁移时尽量复用已有素材和设计。

#### HTML 原型的用途与 Overlay 备选方案

HTML 原型可作为视觉与交互的参考标准，为 Agent 提供明确的布局、动效和页面节奏依据。

另一条实现路线是直接将 HTML 界面叠加在 Godot 网页游戏上。

Godot Web 支持通过 `JavaScriptBridge` 与浏览器页面交互，因此技术上可以在打开画册时显示 HTML 层，关闭时隐藏。


这种方式可以最大程度复用现有 HTML 原型。但会产生两套 UI 和输入体系，需要处理键盘焦点、鼠标捕获、Esc、窗口尺寸和构建发布等集成问题。

当前仍推荐 Godot 原生 UI：项目已有运行中的阅读系统，E03 的交互规模也不大。

若后续 HTML 版本的视觉效果明显优于 Godot 版本，且迁移成本过高，可考虑 HTML Overlay。交付目标为浏览器，因此这一备选方案符合交付条件。

#### 代表性状态验证与推进依据

旧稿建议先由 Codex 制作小规模 Godot E03 技术与视觉 Spike，再导入全部真实照片。

继续保留旧稿的三个代表性验证状态：2020 年双人对照页、真实季度星群经过时间指针（现为小舟）时的依次亮灭、2026 年时间轴平滑放大（按组件稿同屏伸缩实现）。要求在真实的 Godot Web 导出中运行，并与目前 HTML 原型比较效果。

若这三个状态达到预期，其余画册内容主要涉及图片排版和数据填充。

技术评估结论：主要难点在于 Godot 版本能否保留 HTML 原型的美术品质，无需引入更重的 3D 方案，也无需牺牲已设计的时间轴动效。
