# C01：茶几手机 2048 体验与验收

本规格记录已批准的首版，覆盖 [C01 原稿](v1/06-C01-2048.md)中的待定选择。当前实现和验收状态见[当前状态](../status.md)。

## 体验规格

- 客厅茶几放可编辑、尺度匹配的手机，玩家自然靠近后 F 打开 Godot 原生 2048 界面，仍能看见小屋；不模拟完整手机系统或手势。
- 标题、分数、4×4 棋盘及简洁提示；方向键每按一次走一步，忽略长按和动画期间的输入。初始两个随机方块，每个为 90% 的 2 或 10% 的 4。有效移动后仅增加一个随机方块；无效移动不变。相同数值按移动方向合并且每块每步最多一次，分数增加合并结果之和。
- 达到 2048 提示但继续游戏；无合法移动显示结束。重新开始支持鼠标与 Tab/Enter，有进度先确认；Esc 优先取消确认，再退出小游戏。
- 进入释放鼠标并冻结行走和镜头，方向键仅控制棋盘，F/B 不串扰。退出使用现有鼠标恢复流程；失焦或捕获失败提供明确继续入口，不模拟浏览器授权。
- 本次游玩重新进入保留棋局与分数；刷新重置，不添加存档、排行榜、遥测或网络依赖。与王冠、蛋糕、仪式独立，不附加私人台词。

## 工作清单与验收矩阵

执行者负责资产、集成、构建、针对性测试和真实网页操作；独立 reviewer 对当前候选逐项判定 PASS / FAIL / EVIDENCE_GAP；主控检查截图、操作记录与 review 并维护状态。所有项通过后才可交给原会话最终验证。注入、固定站位和模拟授权仅为内部证据，不能替代真实网页玩家路径。

| 编号 | 通过条件 | 执行者与验证方式 |
| --- | --- | --- |
| 1 | 正常试玩入口真实行走至茶几，识别手机 F 提示并进入 | 执行者：网页真实操作，记录起点、动作和截图；reviewer 核对证据 |
| 2 | 手机和邻近沙发目标不抢占，常见方向及合法贴近边缘可进入，退出并再次进入；坐位仍可用 | 执行者：网页自然路径及合法站位引擎检查；reviewer 核对目标和证据 |
| 3 | 四方向、无效步、合并一次、分数与仅有效步生成正确；两个示例左移均为 [4,4,0,0] | 执行者：可控制随机源的确定性引擎测试及网页操作；reviewer 核对结果 |
| 4 | 初始两块、2048 达成后可继续、无合法移动结束；重开及取消确认正确 | 执行者：确定性测试和网页可达流程；reviewer 核对证据边界 |
| 5 | 按键一次一步、长按不连发；角色、镜头、F/B 隔离，Esc 按当前层级退出 | 执行者：引擎输入测试及网页真实操作；reviewer 核对 |
| 6 | 退出重进保留棋局分数，确认重开重置 | 执行者：网页闭环及引擎测试；reviewer 核对 |
| 7 | 失焦、恢复、退出后的真实鼠标捕获、行走与视角正常；失败可明确继续 | 执行者：网页真实输入及失焦操作，模拟授权只算内部证据；reviewer 核对 |
| 8 | 1366×768 默认缩放数字提示完整清晰，1920×1080 布局正常 | 执行者：当前候选网页截图；主控看图，reviewer 检查证据 |
| 9 | 王冠、蛋糕、仪式状态独立；邻近坐位及一次阅读或背包正常 | 执行者：状态测试及受影响的网页回归；reviewer 核对 |
| 10 | 可重建；普通本地试玩真实路径可用 | 执行者：构建记录及网页操作，不用传送或直接调用打开函数代替路径；reviewer 核对 |

## 执行顺序

1. 核对现有交互和资产归属，完成手机、棋盘和输入集成；逻辑使用确定性测试验证。
2. 尽早导出并从正常入口走最小进入、操作、退出、恢复闭环；随后完成受影响范围与双尺寸验证。
3. 独立审查固定候选；失败由实施者修复并针对性复核。记录真实截图、命令和缺口，更新状态及交接。
