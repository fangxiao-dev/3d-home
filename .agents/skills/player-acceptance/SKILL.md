# 玩家路径验收

目标：Agent 先证明玩家能从正常游览到达并使用内容，再把作品交给用户判断氛围、手感和表达。适用于本项目各房间、道具和界面，不限定某个彩蛋。

## 先确定本轮范围

读取根 [AGENTS.md](../../../AGENTS.md) 的轻量验证表、[当前状态](../../../docs/status.md)及本次设计规格。按改动选择问题路径与相邻正常流程；尺寸、独立审查和性能检查沿用本轮要求，避免把阶段验收变成每次小改的全屋回归。

确认当前导出候选及可复用证据。正常版本识别使用现有构建记录，不新增全量哈希清单。修复后只重验受影响路径，未受影响的通过结论继续复用。

## 尽早验证完整入口

入口初步可用时，由执行者在真实浏览器走完以下最短闭环，再继续扩充内部功能；最终候选重验变化的环节。此检查由 Agent 完成，不增加中途用户验收。

1. 从正常试玩入口和常规游览状态出发，自然走到目标附近。
2. 确认提示可发现，提示名称、当前目标与按键实际触发的动作一致。
3. 通过真实输入进入互动并完成核心操作。
4. 退出或取消，确认恢复行走、视角和必要状态，再次进入同一互动。

直接调用打开函数、传送到预设位置或预先注入解锁状态，可用于内部测试；真实路径仍需覆盖此前被跳过的进入过程。

## 覆盖自然位置与失败恢复

- 从玩家会自然停下的位置检查，而不只在程序设定的接近点测试。互动发现位置与动画对齐位置用途不同。
- 有相邻物体时同时检查提示与动作归属，例如书本和椅子；覆盖常见接近方向及贴近碰撞边缘的合法站位。
- 固定站位测试先确认人物没有穿进家具，再驱动真实的交互状态转换；每个已确认故障留下能在修复前失败的回归。
- 对本轮涉及的接近受阻、取消、失焦或界面切换，检查恢复后确实能继续操作并重试。显示失败文案不等于恢复操控。
- 阅读或背包等界面内，检查输入只作用于当前界面；关闭后再次检查游览和相邻正常互动。

## 分清证据与完成状态

| 证据 | 能支持的结论 | 仍需单独验证 |
| --- | --- | --- |
| 引擎检查、固定位置、模拟授权 | 状态、内容完整性、碰撞路径、模拟输入边界 | 自然行走入口、浏览器真实捕获与恢复、实际呈现 |
| 资产渲染、网页截图 | 对应画面的造型、构图、清晰度 | 玩家是否能进入、完成、退出和再次进入 |
| 当前候选的真实网页操作 | 实际走过的玩家路径及输入行为 | 未走过的路径、未检查的尺寸 |

主控结合截图判断玩家看到什么，结合操作结果判断玩家能做什么。执行者提供简短的起点、目标、动作、结果和相关截图；独立 reviewer 按项目要求检查变化范围与证据缺口。主控无需重复已通过的整套操作，但遇到明确疑点需补最小检查。

浏览器检查中断或不可用时，保留“实现候选／网页未验收”，明确缺少哪条路径，继续可独立完成且获准的工作。遵守工具停止要求，恢复条件满足后再补验。用户明确要求时可以提供标注未验收的预览；常规功能验收仍由 Agent 负责，不能默认让用户补测或将引擎通过写成网页通过。

## 完成与回写

交付前确认：本轮玩家闭环有当前候选的真实网页证据，已确认故障回归通过，适用的独立审查已完成，剩余美术表达调整与功能缺口分别列出。缺少其中一项，就按实际范围报告部分完成。

只更新受影响的操作说明或[当前状态](../../../docs/status.md)，复用现有证据位置；无需为每次小修新增报告树。

## 这条经验来自哪里

书桌互动曾出现“书边误选椅子”“椅子周边无入口”和“贴椅背接近受阻”，而理想接近点的内部测试可以通过。现役 [Verify-Study-Access.gd](../../../tests/Verify-Study-Access.gd)覆盖合法周边站位、F 目标与进入退出；其中鼠标授权明确为引擎模拟。该案例支持增加自然入口和边界回归，不代表最终网页验收已经通过；实时结论以当前状态为准。
