# 生日礼物项目｜设计基线与 Session 决策记录

> 版本：V1 基线\
> 状态：已讨论事项的沉淀稿；未明确的内容保留为待决策\
> 用途：作为后续彩蛋设计、场景设计与 Vibe Coding 实现的共同依据

## 1. 项目定位

这是一份为叶莹准备的、可以实际体验的数字生日礼物。当前技术设想是
Blender + Godot，最终以 Web Export 交付；技术路线仍可根据探索结果调整。

当前优先体验不是挑战、解谜或收集任务，而是两种体验：

1.  **安静地翻阅和发现内容。**
    例如阅读实体画册与情书文集、留意沙发上的猫抓痕，以及查看空间里的私人细节。
2.  **亲手完成生日仪式。**
    目前明确的核心动作包括获得并佩戴王冠、准备生日蛋糕、点燃蜡烛，并主动触发生日快乐场景。

探索可以存在，但不作为主要任务结构。作品不需要用大量锁、钥匙、收集物或任务链来延长游玩时间。

## 2. 创意讨论与设计方法

创意讨论分为两个维度：

-   **呈现形式：**
    彩蛋以什么方式进入游戏世界，例如实体画册、实体文集、可交互物品、近距离观察或仪式场景。
-   **创意点：** 实际呈现什么内容，以及这件事为什么值得被记住。

同一个创意点可以使用不同呈现方式；同一种呈现方式也可以承载不同内容。设计时不要把两者混为一谈。

协作原则：

-   Fang 负责提出创意、判断作品方向并作最终选择。
-   助手负责主动引导设计方法、给出明确判断、挑战不成立或过度设计的部分，并协助推演与拆解。
-   背景文档是理解人物与关系的材料，不是产品需求清单。不得因为某个主题在背景中出现，就强行将其做成机制或剧情。
-   先判断创意本身是否成立，再讨论技术实现；不提前用技术限制替代创意判断。
-   已确定的规则作为基线。若新创意需要修改规则，应明确讨论修改原因与影响。

## 4. 已冻结的交互机制 V1

### 4.1 场景内操作

-   使用 `WASD` 移动角色。
-   靠近可交互物品后按 `F` 执行交互。
-   场景内不要求鼠标直接点击 3D 物品。
-   同一时刻应明确当前的主要交互目标；若附近存在多个对象，需要清楚提示按
    `F` 会操作哪一个。

### 4.2 界面内操作

-   可点击 UI 图标打开背包 / 人物状态界面，也可以提供对应键盘快捷键。
-   背包中可用鼠标选中物品，再选择该物品支持的
    action，例如佩戴、取下、打开。
-   重要操作尽量提供键盘替代方式；鼠标不是完成游戏的唯一途径。
-   阅读画册或情书时，使用 `←` / `→` 翻页，`Esc`
    退出；可以支持鼠标点击翻页。
-   打开界面后，输入上下文切换。例如阅读时，左右键负责翻页，不应同时移动角色；退出后恢复场景控制。

### 4.3 状态与反馈

-   交互条件不足时必须给出明确反馈，不能无响应。
-   物品状态在场景、背包、人物示意图和事件条件之间保持一致。
-   同一次游玩过程中，切换界面不应无故重置物品状态或阅读进度。
-   页面刷新或关闭浏览器后是否持久保存进度，尚未确定，留待技术设计阶段决定。

## 5. 统一物品生命周期原则

**统一状态管理规则，不要求所有物品走同一条生命周期。**

已采用的动作术语：

  动作   含义
  ------ ----------------------------
  交互   玩家与场景物品发生操作
  解锁   某项内容或获取机会变为可用
  获取   物品正式进入玩家持有状态
  装备   物品改变人物穿戴状态
  摆放   物品进入指定场景位置
  激活   满足条件后启动某个事件
  观察   查看环境细节；不必获得物品

典型类型：

-   **阅读型：**
    画册、情书文集。可打开、翻页、退出；阅读到指定页面时可触发事件。
-   **状态型：** 王冠。可获取、佩戴、取下。
-   **场景型：** 蛋糕。可从原位置取出、摆放、点燃蜡烛。
-   **环境型：** 猫抓痕。可观察，不要求进入背包或解锁内容。
-   **可交互日常物件：** 2048
    设备、百醇等。交互深度按创意价值和实现成本决定，不默认必须做成完整小游戏或复杂系统。

物品可以同时具有多种能力；并非每件物品都必须进入背包。

## 6. 生日仪式的已确定条件

生日仪式由玩家主动触发，不在准备完成时强制自动播放。

当前条件：

1.  王冠已经获得，且当前处于**佩戴状态**。
2.  蛋糕已经摆放到指定桌面。
3.  蜡烛已经点燃。

条件不足时，给出清晰提示。尤其要区分"王冠已拥有"和"王冠已佩戴"：取下王冠后，生日仪式条件不再满足。

具体生日快乐场景的镜头、动画、音频、台词和结束方式尚未设计。

## 7. 内容组织原则

-   时间画册暂定负责呈现「发生过什么」，更适合时间点、照片与简短记录。
-   情书文集暂定负责呈现「彼此曾经表达过什么」，尽量保留原始文字的语气与完整性。
-   两者可以涉及同一事件，但应提供不同的阅读价值，避免简单复制同一段内容。
-   猫抓痕等环境细节不必承担剧情任务。
-   日常彩蛋不应全部被包装成重大象征；可以有些内容负责让她回忆，有些负责让她笑，有些只是让空间显得真实。
-   不把每个彩蛋都设计成"获取---解锁---奖励"的任务链。

## 8. 当前待决策事项

以下内容尚未敲定，不应在实现前被默认为需求：

-   时间画册究竟采用时间长廊、实体相册、自由翻阅的时间线，还是组合形式。
-   画册收录哪些事件、每页的图文比例与页面数量。
-   情书文集收录哪些文章、如何编排，以及王冠获取提示的具体表现。
-   王冠的具体获取动作：提示出现后自动授予，还是由玩家确认领取。
-   生日蛋糕的具体场景操作表现，以及生日仪式完成后的状态。
-   猫抓痕的具体视觉细节、背景含义与观察反馈。
-   2048 是做成可玩的简化小游戏，还是较轻量的设备交互。
-   百醇以纯环境物件、近距离观察，还是带有文字反馈的交互呈现。
-   Web 刷新后是否保存进度。
-   最终美术风格、场景尺寸、角色表现、音效与技术架构细节。
