- 创意和实现可以在多个对话同时推进，不要求先完成全部剧本。
- 用户已提供人物与关系背景；下一阶段由用户提出具体 idea，agent 基于背景讨论实现。每个新对话必读 [背景入口](background/README.md)，按任务再读全文与原始情书；背景主题不自动转为剧情、彩蛋或美术要求。
- 初始参考图展示卡通人物、简化家具和柔和灯光；最终美术风格通过可见结果继续对齐。
- 2026-10-16 用户确认现有家具已经可以，偏好清爽简化的画面：家具和环境不投影，只保留人物脚下阴影；不继续追求 Blender 离线渲染的阴影精度。
- 画面应整体柔和、明亮暖光，避免冷灰；白色沙发和墙面仍应保留可辨的层次。仅提高亮度的版本仍被用户指出偏灰，后续需同时检查暖光色调。简单画面参数调节交给可复用的子 agent，主控负责最终验收。
- 技术选型已确定为 Blender + Godot 标准版 / GDScript / Compatibility 渲染 / Web 导出；安装与操作说明以 [README.md](README.md) 为准。

- 同日确认客厅内宽 5.8 m、纵深 5.8 m、层高 3.3 m：左右墙与两侧家具组各向外平移 0.75 m，家具体量保持，中央留白加宽。尺寸用于卡通画面比例。

## 已确认的全屋空间范围

2026-10-17 用户确认以下分级，作为后续建模、通行与互动范围的唯一权威清单。分级表示已选定的设计，不表示所有空间已经制作完成。

| 等级 | 空间 | 展示与游玩规则 |
| --- | --- | --- |
| 主要空间 | 客厅、餐厅、书房、走道 | 可以进入，是后续故事与互动的主要承载区域；具体彩蛋另行确定。 |
| 次要空间 | 阳台、洗漱台 | 可以进入，保留代表性设施与空间氛围，不设置互动、互动标记或 F 提示。 |
| 仅展示空间 | 厨房 | 从开放区域能看见内部，人物无法进入，不设置互动、互动标记或操作提示。 |
| 不开放空间 | 其他所有空间 | 从开放区域只看见关闭的门，不展示内部、不提供开门互动、互动标记或操作提示。 |

“洗漱台”指布局图中的独立洗漱区，后方厕所不开放。卧室、杂物间等按关闭房门处理；隐藏区域内部的房间和房门不制作。

当前已完成的是客厅基础模型与玩法。餐厅、书房、走道、可进入的阳台与洗漱区，以及厨房展示内部均已入选、尚未制作；现有阳台开口和远端窗框只是客厅版本的边界提示。

后续粗版以现有客厅为风格基准，沿全局布局图建立空间关系，比例服务于宽敞、清爽的卡通画面。验收时，主要与次要空间应构成可走通的路线；厨房可见但无法进入；关闭房门后不能窥见房间内部。新增故事与互动按用户后续确认制作。
